Avatar Chat マニュアル

OpenAI互換のLLMとおしゃべりすると、返事の内容に合わせてアバターの表情が変わるチャットです。このマニュアルは start.bat と同じフォルダに入っています。

1. Avatar Chat とは

  • 表情が変わる … 返事のたびにLLMが気持ち(うれしい・かなしい…)を選び、その表情の画像に切り替わります。
  • キャラごとの記憶 … 会話から覚えておくべきことを自動でメモし、時間とともに薄れていきます。キャラ同士では共有されません。
  • キャラを増やせる … 好きな画像で自分のキャラを追加できます(7・8章)。
  • ネット検索・天気 … 必要なときだけ調べて答えます(6章。Brave検索のAPIキーが必要)。
  • 5か国語の画面 … 日本語・English・简体中文・Español・Português。
  • 自分のPCだけで動く … 会話・記憶は自分のPC内(user-data)に保存されます。外に出るのは、LLMへの送信(自分のサーバーなら外に出ません)と、ネット検索を使ったときの検索語だけです。

2. 起動と終了

はじめて起動する

  1. start.bat をダブルクリックします。黒い画面が開き、初回だけ Python などを自動でダウンロードします(インターネット接続が必要。数分かかります)。
  2. 続いて「ローカルLLMのセットアップ」のメニューが出ます。数字キーを押すだけで選べます。
    選択どんなとき
    1 RadeonAMDのグラフィックカード。Vulkan版のllama.cppを入れます。IntelのGPUや内蔵GPUでも動くかもしれません(未確認です。内蔵GPUはメモリを共有するため、遅くなったり動かなかったりすることがあります)。
    2 GeForce RTX 20系以降NVIDIAのグラフィックカード(VRAM 8GB以上)。CUDA版を入れます。
    3 すでにLLMサーバーがあるLM Studio・Ollama・llama.cppなどを使う人。接続先だけ登録します(サーバー自体は入れません)。
    4 あとで設定する今は何もしない。あとで「設定」画面で自分で入力します。
    メニューの上に、お使いのグラフィックカード名が表示されます。迷ったらそれを見て選んでください。
  3. 1・2を選ぶと、llama.cpp・llama-swap・モデル(Stheno v3.4 8B、約4.9GB)を自動でダウンロードします。サーバーに負担をかけないよう、モデルはわざとゆっくり(約17分)ダウンロードします。黒い画面は閉じないでください。閉じても、次に start.bat を開けば続きから再開します。
    2つ目のモデル(Lumimaid v0.2 8B)も入れるか聞かれます。迷ったら「1 いいえ」でOKです。
    注意: Stheno も Lumimaid も、すでに少し古いモデルで、日本語は弱めです(言い回しが不自然になったり、文がおかしくなったりすることがあります)。VRAM 8GB で動かせる範囲での割り切りです。日本語の質を上げたい場合は、より大きなモデルや、ほかのモデルに llama-swap\config.yaml で差し替えてください(VRAM が足りないと動きません)。
  4. 終わるとブラウザが自動で開き、チャット画面が出ます。開かないときは、ブラウザで http://127.0.0.1:8765 を開いてください。
2回目からはメニューは出ません。start.bat をダブルクリックするだけです(LLMサーバーも一緒に起動します)。

終了する

  • アプリの黒い画面(start.bat の画面)を閉じます。
  • セットアップで入れたLLMサーバー(llama-swap)は別の小さなウィンドウ(タスクバーに最小化)で動いています。使い終わったらそちらも閉じてください(閉じるとGPUのメモリが空きます)。
  • 会話中にいきなり閉じても、直前までの会話は保存され、まだ記憶に整理されていない分は次回起動時に整理されます。

セットアップをやり直したい

misc フォルダの setup-llm.bat をダブルクリックします(同じメニューが出ます)。ダウンロード済みのファイルは再利用されます。

3. 画面の見かた

左:キャラ一覧キャラを選ぶ/＋キャラ追加/言語の切り替え/設定
中央:会話上にアバターと名前、下に会話ログと入力欄。入力欄の横で検索のモードを選べます。
右:記憶そのキャラが覚えていること。バーが短いほど忘れかけています。

会話する

  • 下の入力欄に書いて送信ボタン(またはEnter)で送ります。改行はShift+Enter。
  • 返事が来るとアバターの表情が変わります。しばらくすると元の表情(ふつう)に戻ります。
  • 返事が遅いときは「…」が出ています。モデルを読み込む最初の1回は特に時間がかかります。
  • キャラが記憶を思い出して返事したときは、会話の下に「思い出したこと」が薄く表示されます。

ボタン

ボタンはたらき
会話を消すそのキャラとの会話ログを消します。消す前に、まだ覚えていない内容を記憶に整理するので、記憶は残ります。
キャラ削除自分で追加したキャラだけに出ます。会話と記憶もすべて消え、元に戻せません。組み込みキャラ(もち・ほのか・レイ)は削除できません。
右の記憶の「×」その記憶ひとつを消します。まちがって覚えてしまったときに使います。

4. 設定

左下の設定ボタンで開きます。変更したら保存を押します。

項目意味
接続先URLLLMサーバーのアドレス。セットアップした場合は http://127.0.0.1:8080/v1。LM Studioは http://127.0.0.1:1234/v1、Ollamaは http://127.0.0.1:11434/v1。
APIキー自分のPC内のサーバーなら空でOK。外部サービスを使うときだけ入れます。保存後は「設定済み」と出ます。
モデル名使うモデル。右の「一覧を取得」を押すと、サーバーにあるモデルが候補に出ます。入力欄をクリックすると全候補が出て、文字を打つと絞り込めます。セットアップ済みなら stheno-8b(2つ目を入れた場合は lumimaid-8b も)。
あなたの呼び名キャラがあなたを呼ぶ名前。
Brave Search APIキーネット検索を使うときだけ。6章を見てください。
検索の国コード / 件数検索結果の国(JP など)と、取得する件数(1〜10)。
アバターの動きアバターの待機モーションを「入/OSの設定に従う/切」から選びます(この画面だけの設定)。動きが気になるときは「切」。
温度返事のばらつき。大きいほど自由で、小さいほど堅実(既定 0.8)。返事が崩れるときは 0.5〜0.7 に下げると安定します。
履歴の往復数毎回LLMに渡す直近の会話の量(既定 12往復)。増やすと文脈を覚えやすいですが、重くなります。
記憶を整理する間隔あなたが何回発言するごとに記憶を整理するか(既定 2)。小さいほど早く覚えますが、LLMを呼ぶ回数が増えます。
記憶の基準日数大きいほど忘れにくい(既定 10日)。5章を見てください。
APIキーの保存キーは user-data\config.json に平文で保存されます。このフォルダを他人に渡したり、ネットに公開したりしないでください。

5. 記憶のしくみ

  • 数回話すごとに、LLMが「覚えておくべきこと」(名前・好み・約束など)を取り出してメモします。
  • メモには重要度(1〜5)がつきます。重要なほど長く残ります。
  • 時間がたつと強さ(バーの長さ)が下がります。でも話題に出て思い出されるたびに、強くなり、忘れにくくなります。
  • 強さが小さくなりすぎた記憶は、思い出されなくなります。
  • 記憶はキャラごとに分かれています。「もち」に話したことを「ほのか」は知りません。
  • タブを閉じる・「会話を消す」・次回起動時にも、整理しきれていない会話は自動で記憶に整理されます。

覚え間違いは右の記憶の「×」で消せます。

6. ネット検索と天気

最新の話題や、知らないことを聞かれたとき、ネットを検索して答えに使えます。

  1. Brave Search API(外部サイト)でAPIキーを取得します。
  2. 設定 → Brave Search APIキー に貼り付けて保存します。
  3. 入力欄の横のメニューでモードを選びます。
    • 🔍 自動 … 必要だとキャラが判断したときだけ検索(既定)。
    • 🔍 毎回 … 毎回検索。
    • 🔍 なし … 検索しない。
  • キーが未設定のときは、メニューが「🔍 キー未設定」になります。クリックすると設定画面が開きます。
  • 検索したときは、会話の下に「検索した語」と出典のリンクが表示されます。
  • 日本の地名つきの天気の質問(例:「明日の福岡の天気は?」)は、検索ではなく気象庁の公式データで答えます(英語などでも可)。検索モードが「なし」でないときに働きます。現在の画面の仕様では、Brave Search APIキーを設定していないと検索モードが使えず、天気もこの機能は働きません(天気の取得そのものにはキー代は不要です)。
プライバシー検索を使うと、検索語が Brave に送られます。会話の全文は送られません。

7. キャラを追加する

  1. 左の＋キャラ追加を押します。
  2. 次を入力します。
    項目書くこと
    名前必須。
    性格・口調の設定キャラの人格の元になります。書き方は8章。
    最初のあいさつ省略可。キャラ選択時、最初に表示されます。
    アバターの動き方「生き物・デフォルメ」か「人間型」(違い)。
    表情画像neutral(ふつう)は必須。ほかは省略可。足りない表情はneutralで代わりに表示されます。
  3. 追加を押すと、キャラ一覧に増えます。

追加したキャラは user-data\characters に保存されます。削除はそのキャラを選んでキャラ削除です。

まず neutral だけで試す最初は neutral の1枚だけで追加して、動きを確かめてから、ほかの表情を足していくのがおすすめです。画面からの追加は新規作成のみで、あとから画像を差し替えるにはキャラを作り直すか、ファイルを直接置き換えます。

8. アバターの作り方

アバターは「表情ごとの画像」を入れ替えて見せているだけです。絵が描ける人も、画像生成AIを使う人も、同じ手順で自分のキャラを作れます。

画像の仕様

項目内容
形式PNG・JPEG・WebP など(画面から追加するとき)。SVGは画面からは追加できません(ファイルで置く場合のみ可)。
背景透過(背景なし)がおすすめ。背景つきでも使えますが、四角い枠が見えます。
大きさ自動で長辺768px以内のWebPに変換されます(縮小のみ。小さい画像は拡大されません)。表示は高さ300px程度なので、512〜768px四方もあれば十分です。
枚数neutral必須+最大7枚(計8表情)。
向き・構図全身でも上半身でも可。ただし表示が小さいので、顔がはっきり見える構図にしてください。

8つの表情

LLMは、次の説明を見て「今の返事にはどの表情が合うか」を選びます。

名前日本語使われる場面
neutralふつう(必須)落ち着いた会話。ふだんの顔。
happyうれしいうれしい・楽しい・ほめられた。
sadかなしい悲しい・残念・落ち込んだ。
angryおこる怒り・不満・ぷんぷん。
surprisedおどろく驚き・予想外のこと。
embarrassedてれる照れ・恥ずかしい。
thinkingかんがえる考え込む・迷う。返事を待っている間にも出ます。
sleepyねむい眠い・のんびり・退屈。

全部そろえなくても動きますが、neutral・happy・sad の3つがあると印象がだいぶ変わります。

作るときのコツ

  • 同じ人に見えることが一番大事です。表情ごとに顔立ち・髪型・服が変わると、別人に見えてしまいます。
  • 画像生成AIで作る場合
    • まず neutral を1枚決めます。
    • ほかの表情は、同じシード・同じプロンプトのまま、表情に関する言葉(笑顔・泣き顔・怒り顔など)だけを差し替えて生成します。
    • もっと安定させたいときは、neutral を元画像にして、変化を弱めに(元画像を強く残す設定で)画像→画像で作ります。
    • 生成のたびに、顔・髪・服・リボンなどの小物が変わっていないか確認し、変なものが写り込んだ画像は作り直します。
  • 絵を描く場合 … neutral を描いてから、目・眉・口だけを描き替えるのが楽です。全表情で同じキャンバスサイズにします。
  • 背景の透過 … 背景が単色になるよう生成/描画して、切り抜きツール(画像編集ソフトの「背景を削除」など)で透過PNGにします。
  • キャンバスと足元をそろえる … 表情ごとにキャラの大きさや位置がずれると、切り替えたときにアバターが跳ねて見えます。全表情で同じ大きさのキャンバス、同じ位置にしてください。アバターは足元を支点に動くので、足元(下端)を揃えるのが大切です。
  • 権利に注意 … 他人が描いた絵や、利用条件のあるモデル・素材は、そのルールに従ってください。公開・配布するときは特に確認を。

動き方の選び方

種類動き向いているキャラ
生き物・デフォルメ(squash)つぶれたり伸びたりして、はずみます。うれしいときは跳ねます。マスコット・動物・不思議な生き物。
人間型(soft)体は歪めず、上下とごく小さな傾きだけ。人間のキャラ。

人間の絵を「生き物」にすると、体がぐにゃっと歪んで不自然に見えます。人間型にしてください。動きが邪魔なときは、設定のアバターの動きで切れます。

性格設定の書き方

「性格・口調の設定」は、そのままLLMに渡されます。短く具体的に書くほど、小さなモデルでも安定します。組み込みキャラ(characters フォルダの character.json)が見本になります。

  • 基本情報 … 年齢・一人称・あなた(相手)への気持ち。
  • 話し方 … 口癖や語尾、例文を3〜4個。例文が一番効きます。
  • ふるまい(箇条書き) … 例:「返事は1〜3文」「聞かれたことに答える。同じ言葉を繰り返さない」「わからないことは素直に『知らない』と言う」。
  • 表情のきっかけ … 例:「本気で褒められたら照れる」と書くと、embarrassed が出やすくなります。
例:のんびり屋の謎の生き物。一人称は「ぼく」。語尾に「〜もち」を付ける。
【話し方】ゆっくり、やさしく。例: 「おはようもち」「それはすてきもち」
【ふるまい】
- 返事は1〜3文。
- 聞かれたことに答える。同じ言葉を繰り返さない。
- 褒められると照れる。

ファイルで作る(上級)

画面からでは足りないとき(SVG画像を使う、表情を8つ以外に増やす、設定を直すなど)は、フォルダとファイルを直接作れます。

  1. user-data\characters の中に、好きな名前(英数字)のフォルダを作ります。例: user-data\characters\sakura
  2. そこに表情画像(png / webp / svg など)と character.json を置きます。
  3. ブラウザを再読み込みします(F5)。
{
  "name": "さくら",
  "persona": "のんびりした18歳の女の子。…",
  "greeting": "こんにちは。来てくれたんだね。",
  "motion": "soft",
  "fallback": "neutral",
  "emotions": {
    "neutral": { "file": "neutral.webp", "hint": "ふつうの状態。落ち着いた会話" },
    "happy":   { "file": "happy.webp",   "hint": "うれしい・楽しい・褒められた" },
    "sad":     { "file": "sad.webp",     "hint": "悲しい・残念・落ち込んだ" }
  }
}
  • motion は soft(人間型)か squash(既定)。
  • fallback は、該当する表情がないときに使う表情(通常は neutral)。
  • hint は「この表情をどんなときに使うか」の説明で、LLMがこれを読んで選びます。書き換えると、そのキャラだけ表情の出方を変えられます。省略すると標準の説明が使われます。
  • 表情名を8つ以外に増やすこともできます(例: shy)。その場合は hint を必ず書いてください。
  • 編集前に、user-data をバックアップしておくと安心です(10章)。JSONの , や " を間違えると、そのキャラが一覧から消えます。

9. 言語の切り替え

左下の言語メニューで、日本語・English・简体中文・Español・Português を選べます。切り替えると次のものが変わります。

  • 画面の文字、エラーなどのメッセージ。
  • 組み込みキャラ(もち・ほのか・レイ)の名前・性格・あいさつ。
  • キャラの返事の言語(その言語で返事するよう指示します)。

自分で追加したキャラの名前・設定・あいさつは、書いた言語のままです。

注意
  • 英語・中国語・スペイン語・ポルトガル語の画面と組み込みキャラの翻訳は機械翻訳で、ネイティブの確認はしていません。不自然な表現があるかもしれません。
  • モデルによって得意な言語が違います。Stheno などの小型モデルは、英語が最も安定します。日本語は弱めです。
  • 言語を切り替えても、すでにある会話ログの言語は変わりません。
  • このマニュアルは日本語のみです。

10. データ・バックアップ・更新

フォルダ / ファイル中身消すと
user-data\設定(config.json)・会話と記憶(app.db)・追加したキャラ全部消えます。これだけバックアップすれば引っ越し可能。
system\自動で入れたPython一式次回起動時に作り直し(再ダウンロード)。
llama.cpp\ llama-swap\ローカルLLMの実行ファイルmisc\setup-llm.bat で入れ直し。
models\LLMのモデルファイル(1つ約4.9GB)再ダウンロード。
misc\downloads\ダウンロードしたzipの置き場消してOK(容量が空きます)。

バックアップ

アプリを閉じてから、user-data フォルダを丸ごとコピーします。戻すときは、同じ場所に上書きコピーします。

更新する

  1. 新しい zip を展開します。
  2. 中の app・characters・misc フォルダと start.bat・manual.html を、今のフォルダに上書きコピーします。
  3. start.bat で起動します。

user-data・system・models などは zip に入っていないので、上書きしても消えません。

11. 困ったとき

症状確認すること
「モデル名を設定画面で…」と出る設定 のモデル名が空です。「一覧を取得」で選んで保存してください。
返事が来ない/「接続できない」などのエラーLLMサーバーが起動していますか。セットアップした場合は、タスクバーに小さな llama-swap のウィンドウがあるか確認。なければ start.bat をもう一度。LM Studio・Ollama は先にそれぞれを起動します。接続先URL が合っているかも確認してください。
最初の返事がとても遅い最初の1回はモデルをGPUに読み込むため、数十秒かかります。2回目以降は速くなります。
いつも遅い/途中で止まるGPUのメモリ不足かもしれません。ほかのアプリ(ゲーム・画像生成など)を閉じる、設定の履歴の往復数を減らす、llama-swap\config.yaml の -c 8192 を -c 4096 にする、を試してください。
返事の形式が崩れる、同じことを繰り返す温度を 0.5〜0.7 に下げる。それでも直らないときは別のモデルを試します。アプリ側でも、崩れた返事は読み取り直しと再試行をします。
表情が変わらないそのキャラに表情画像が1枚(neutralだけ)しかないかもしれません。表情を足してください。
記憶が増えない数回話すごとに整理されます。記憶を整理する間隔を小さくする、または会話を消すで今までの分が整理されます。
ブラウザが開かない手動で http://127.0.0.1:8765 を開いてください。ポートが使用中のときは自動で次の番号(8766…)になります。黒い画面に出ているアドレスを見てください。
検索が動かないBraveのキーが未設定、または入力欄横のメニューが「なし」です。6章を見てください。
セットアップのダウンロードが失敗したインターネット接続を確認して、もう一度 start.bat(または misc\setup-llm.bat)を開きます。続きから再開します。
キャラが一覧から消えたcharacter.json の書式ミスの可能性があります。8章のファイルで作るの例と見比べてください。

12. 付録: 作る人向けの道具(上級)

アバターの画像づくりや配布物づくりに使う、コマンドラインのスクリプトです。普通に使うだけなら、この章は読まなくて大丈夫です。どれも misc フォルダに入っています。

前提コマンドは、start.bat と同じフォルダで、コマンドプロンプトか PowerShell を開いて実行します。start.bat で入る Python(system\python\python.exe)を使います。下の例の py は、これを短く書いたものです。
set py=system\python\python.exe(コマンドプロンプト)/ $py = "system\python\python.exe"(PowerShell)
スクリプト何をするか実行のしかた
gen_images.pyComfyUI に、表情ごとの立ち絵を自動で生成させる%py% misc\gen_images.py 設定.json
make_sprites.py生成したPNGの白い背景を透明にして、WebP(768px以内)にする%py% misc\make_sprites.py PNGのフォルダ 出力フォルダ
make_zip.py配布用の zip を作る(user-data や models などは入らない)%py% misc\make_zip.py
smoke_test.pyダミーのLLMでアプリを動かして、動作を一通り確かめる%py% misc\smoke_test.py

表情の立ち絵を自動で作る(gen_images.py → make_sprites.py)

同じキャラの8つの表情を、まとめて作る流れです。ComfyUI が動いていて、モデルが入っている必要があります。

  1. 設定ファイル(JSON)を作ります。下の例を、コピーして直してください。
  2. ComfyUI のアドレスを、環境変数 COMFY_HOST で教えます(未設定なら http://127.0.0.1:8188)。
    set COMFY_HOST=http://127.0.0.1:8188
  3. %py% misc\gen_images.py 設定.json を実行します。表情ごとに1枚ずつ作り、outdir に 表情名.png で保存します。特定の表情だけ作り直すときは、あとにカンマ区切りで付けます(例: 設定.json sad,happy)。
  4. %py% misc\make_sprites.py PNGのフォルダ 出力フォルダ で、背景を透明にした WebP にします。この変換で、PNG に埋め込まれたプロンプトなどの情報は消えます。
  5. できた WebP を、キャラの追加の画面から登録します。
{
  "outdir": "misc/gen/mychar",
  "prefix": "avt_mychar",
  "checkpoint": "モデルのファイル名.safetensors",
  "width": 832, "height": 1216, "steps": 28, "cfg": 5.5, "seed": 12345,
  "base": "1girl, solo, long hair, white blouse, upper body, simple background, white background",
  "negative": "worst quality, low quality, bad anatomy, text, watermark",
  "variants": {
    "neutral": "closed mouth, light smile",
    "happy": "bright smile, open mouth",
    "sad": "sad, teary eyes",
    "angry": "angry, furrowed brow",
    "surprised": "surprised, wide eyes, open mouth",
    "embarrassed": "embarrassed, blush, looking away",
    "thinking": "thinking, hand on own chin, looking up",
    "sleepy": "sleepy, half-closed eyes"
  }
}
  • base は全部の表情で共通の見た目、variants は表情ごとに足す言葉です。seed と base を変えないことで、顔立ちがそろいます(作るときのコツ)。
  • 基準になる1枚から表情だけ変えたいときは、"init_image": "基準画像.png" と "denoise": 0.6 のように足します(denoise が小さいほど元の絵に近くなります)。表情ごとに変えたいときは "variant_denoise": {"sad": 0.7}。
  • 背景を透明にする処理は、白(単色)の背景を前提にしています。base に white background を入れてください。
  • 1枚あたり数十秒かかります。5分たっても終わらないと、その表情はエラーになります。
  • ComfyUI のワークフローは、基本的な1モデル構成(checkpoint → KSampler → 保存)のものを自動で組み立てます。LoRA や ControlNet は使えません。

配布用の zip を作る(make_zip.py)

プロジェクトのフォルダから、user-data(会話や設定)、system、downloads、llama.cpp、llama-swap、models、作業用の gen を除いた zip を作ります。出力先は、プロジェクトの1つ上の avatar-chat-dist\avatar-chat.zip です。別の場所にしたいときは、最後に出力先を付けます(例: %py% misc\make_zip.py C:\temp\a.zip)。

動作確認(smoke_test.py)

一時フォルダにプロジェクトをコピーして、ダミーのLLMでアプリを起動し、画面から使うAPIを一通り試します。最後に RESULT: ALL PASSED と出れば成功です。あなたの user-data には触れません。コードを直したあとの確認に使います。

注意これらのスクリプトは、作者の環境(Linux)で作り、動かしてきたものです。Windows の system\python で、すべて実際に試したわけではありません。動かないときは、エラーの内容を手がかりに調べてください。
